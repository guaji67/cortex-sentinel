# 哨兵工作台：需求与边界

2026-09-21 用户纠偏后的实现契约。属于哨兵，不属于 Cortex 产品仓的另一套服务。

## 原意

- 人看结构，AI 看完整事实。首屏不是文章列表：紧凑分组地图、短状态、局部展开。
- 参考负责人工作台的全产品责任域、Harness 图的分组与接缝、自动化图的交付颜色。
- Harness/自动化只是两份已登记资料，不是导航或机器分工的程序规则。
- 新板块可以先是一段研究，也可以任意层级生长；共同协议只约束身份、链接、修订和证据。
- 机器忙、工单在做、代码已合、用户拿到并验过，是四类不同事实。
- 整套前后端直接在 cortex-sentinel 开发、打包和更新。不能保留另一套对外旧工作台。

## 运行设计

哨兵进程内的原生工作台服务负责 HTTP、认证、修订事务和持久化；网页静态资产随
同一个 App 签名、更新。看板不需要 Python、Node、源码仓或额外 launchd 服务。
机器/执行读数直接读取 SentinelStore，使用与原生面板相同的合并与时效规则。

一台明确选择的哨兵保存共享账，其余机器连接它；不自动选主、不默默生成第二份账。
Bonjour 复用现有发现实现。连接资料保存在 App 数据目录，升级不覆盖；多写方采用
修订冲突和幂等事件，而不是最后写入覆盖。离线不伪装成功，不自动分叉写账。

Multica CLI 是可选上游，只在保存账的机器上同步。同步失败保留上一份完整快照并
标明过期，不把部分分页结果发布。原始 HTML 是迁移/发布适配器，不是长期强制格式。
旧资料、草稿、问题历史和源文件保留并迁移；旧服务只在新服务实测通过后退役。

## 验收

1. 同宽视口对照三张参考：板块页首先给完整紧凑地图，点击才看正文。
2. 不修改网页代码登记第三个板块；目录、全景、搜索和关系自动可见。
3. 更换机器/维护者只改数据；缺数据说未知，不能绑定机器名。
4. 远端读写、并发冲突、重复提交、未授权、超限、断网、旧数据迁移有测试。
5. App 包含前端与后端；从安装后的新进程打开并真实验证，不以测试或 PR 代替交付。
6. 大屏可常驻，但不拿负载/提交量冒充产品质量；关闭票不自动变成验证通过。

## 网络边界

共享只面向可信局域网。数据接口须本机同源或配对认证；写方另有板块权限。
不把密钥嵌入网页资产、日志或仓库。不建议公网映射 HTTP；跨外网用现有 VPN/SSH 隧道。
Skill/Hook 多机管理见 [第二阶段协议](ai-management-design.md)：复用本进程网络和生命周期，执行规则信任与看板浏览配对分开。
